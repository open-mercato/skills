# Contract format — .uxproof/

The manual-extraction fallback writes the same four files `npx uxproof init`
generates. Shapes below are the minimum; extra fields are allowed.

## contract.json

```json
{
  "version": 1,
  "framework": "next | react | vite-react | unknown",
  "styling": { "system": "tailwind | css | css-in-js", "tokenSources": [{ "file": "src/app/globals.css", "tokenCount": 42 }] },
  "componentRoots": [{ "dir": "src/components", "fileCount": 12 }],
  "nativeEquivalents": [{ "element": "button", "component": "Button" }],
  "archetypes": [{ "kind": "list", "count": 8, "examples": ["src/app/orders/page.tsx"] }],
  "counts": { "tokens": 42, "colorTokens": 18, "components": 12 }
}
```

## tokens.json

Array of `{ "name": "primary", "value": "#111827", "kind": "color | size | shadow | font | alias | other", "source": "src/app/globals.css" }`. Two additive conventions for declared design values: `source` may be the sentinel `"design"` (a declared token with no code behind it yet) or `"proposed"` (a palette derived from colors already in the code), and an optional `"theme": "light" | "dark" | "both"` field carries the theme of the value. Readers that ignore both see a flat list.

## components.json

Array of `{ "name": "Button", "file": "src/components/Button.tsx", "root": "src/components" }`.

## conventions.md

Human-readable house rules with generated sections (stack, tokens, components,
screen shapes) and a fenced manual section:

```markdown
<!-- uxproof:manual-start -->
The team's judgment calls live here and survive regeneration.
<!-- uxproof:manual-end -->
```

The manual section is the local-override surface for every UX skill: it
extends the generated rules and, on conflict, wins.

## Optional additive fields (layers, guards, design-tool mapping)

Everything below is optional. A reader that ignores it still sees the flat
contract above, and the `version` stays `1`: nothing here changes the meaning of
an existing field.

- `contract.json` → `layers`: one entry per design system imported by
  `references/design-sources.md`, in import order:

  ```json
  "layers": [{
    "origin": "dependency | repo",
    "name": "<dependency name | repo-relative directory>",
    "version": "<installed version | null for a repo-owned layer>",
    "files": ["<contract files read, relative to the layer root>"],
    "guides": ["<UI guide files, relative to the layer root — pointers, never copies>"],
    "imported": { "tokens": 0, "components": 0, "archetypes": 0, "guards": 0 },
    "shadowed": 0
  }]
  ```

  `version` is the stamp consumers compare with the installed dependency: a
  mismatch means the imported facts describe another release.
- `contract.json` → `archetypes[]` may carry `anatomy` (a string naming the
  screen's regions in order and the components that fill them), `requiredStates`
  (state names every screen of that shape must cover, for example
  `["loading", "empty", "error"]`) and `origin`.
- `tokens.json` and `components.json` entries may carry `origin` (the layer
  `name`; absent means extracted from this working tree). A token may carry
  `designName` (the variable or style name in the team's design tool); a
  component may carry `designComponent` (its name in the design-tool library).
  These two fields are the design-tool mapping the design-file skills use.

## guards.json (optional, never generated by the extractor)

Deterministic conformance rules, written by the team or imported from a layer.
The extractor never writes or reads this file, so a refresh cannot drop it.

```json
{
  "version": 1,
  "exemptMarker": "design-skip",
  "rules": [{
    "id": "no-raw-status-color",
    "severity": "critical | warning | info",
    "files": ["**/*.tsx"],
    "forbid": "<extended regex matched per line>",
    "unless": "<optional regex; a match on the same line exempts it>",
    "fix": "<the token, component, or pattern to use instead>",
    "why": "<one line: the user-visible consequence>",
    "origin": "<layer name; absent for team-authored rules>"
  }, {
    "id": "list-needs-empty-state",
    "severity": "critical",
    "files": ["**/page.tsx"],
    "when": "<regex: the file is of this shape>",
    "require": "<regex the same file must also match>",
    "fix": "<...>",
    "why": "<...>"
  }]
}
```

A rule has either `forbid` or the `when` + `require` pair, never both. A line
that carries `exemptMarker` followed by a reason is exempt from `forbid` rules;
a marker without a reason is itself a finding. Team-authored rules win over a
layer rule with the same `id`. Severity means: `critical` — breaks a user-visible
contract (theme, state coverage, accessibility, behavior of a house control);
`warning` — drift that will cost consistency; `info` — cosmetic.
