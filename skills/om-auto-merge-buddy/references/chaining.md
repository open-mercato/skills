# Merge-stage chaining

Entry point of the merge stage; run it by hand, on a schedule, or from CI. It consumes the tracker's `automerge`-labeled PR queue, not a previous skill's output. It invokes, each by exact name and in `--orchestrated` mode: `om-auto-review-pr` (signal 1, plus fixes for QA failures), `om-auto-qa-pr` (signal 2) and `om-auto-fix-pr` (signal 3). It also invokes `om-followup-issue-from-pr` once per untracked, intentionally deferred finding, using a specific actionable comment URL; an unavailable helper leaves a visible pending follow-up, never an invented issue (`references/followups.md`). A sub-skill that is missing, or too old to accept `--orchestrated`, parks the PR as `automerge-blocked` and names the skill to install or upgrade. When a sub-skill carries a fork PR forward, it reports the replacement as `replacement=<n>`, and this skill continues on the replacement in the same run (`references/stages.md`). It continues its own previous run when that run's window ended with work left, or when it died with an open handoff (`references/run-log.md`). It ends with one report line per PR it touched and the run folder path, followed by `PR: #<n> (link: <url>)` lines for each.
